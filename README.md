# skycmd

**Tiny "System One" decision models, trained from scratch in Rust on a MacBook and playing games live in your browser through WebAssembly.**

[Play](https://maxgfr.github.io/skycmd/play/) · [Live](https://maxgfr.github.io/skycmd/live/) · [Results](https://maxgfr.github.io/skycmd/results/) · [Install](https://maxgfr.github.io/skycmd/install/) · [Tutorial](https://maxgfr.github.io/skycmd/tutorial/) · [Bench](https://maxgfr.github.io/skycmd/bench/) · [Hugging Face](https://huggingface.co/maxgfr)

Every model has a card and a browser demo on Hugging Face: [s6-nano](https://huggingface.co/maxgfr/s6-nano), [s6-micro](https://huggingface.co/maxgfr/s6-micro), [s6-secrets-pico](https://huggingface.co/maxgfr/s6-secrets-pico), [s5-lite](https://huggingface.co/maxgfr/s5-lite), [s4-micro](https://huggingface.co/maxgfr/s4-micro), [s3-pico](https://huggingface.co/maxgfr/s3-pico), [s1-pico](https://huggingface.co/maxgfr/s1-pico), [s2-nano](https://huggingface.co/maxgfr/s2-nano), [s2-nano-doom](https://huggingface.co/maxgfr/s2-nano-doom), the tool router [s6-route](https://huggingface.co/maxgfr/s6-route) (once uploaded; its pass is on fresh slates, with a system defined after v2's test was read), and the end-of-turn detector [s6-ear2-nano](https://huggingface.co/maxgfr/s6-ear2-nano) (once uploaded; its gate passed, card only, no demo) (published with `scripts/hf-publish.py`). The s6 models that failed their gates are there too, as results, each card opening with its failure: [s6-micro-v1](https://huggingface.co/maxgfr/s6-micro-v1), [s6-ear-nano](https://huggingface.co/maxgfr/s6-ear-nano) and [s6-cast-pico](https://huggingface.co/maxgfr/s6-cast-pico) with a demo, [s6-secrets-verify-pico](https://huggingface.co/maxgfr/s6-secrets-verify-pico) and [s6-route-nano](https://huggingface.co/maxgfr/s6-route-nano) with a card, and with a demo Space once uploaded (every published model gets a Space, failed gates included: owner's decision of 17/11/2026).

The datasets are on Hugging Face too, one parquet config per source with its licence: [skycmd-decisions](https://huggingface.co/datasets/maxgfr/skycmd-decisions), [skycmd-games](https://huggingface.co/datasets/maxgfr/skycmd-games), [skycmd-numeric](https://huggingface.co/datasets/maxgfr/skycmd-numeric), [skycmd-secrets](https://huggingface.co/datasets/maxgfr/skycmd-secrets), [skycmd-commands](https://huggingface.co/datasets/maxgfr/skycmd-commands), [skycmd-zero-shot](https://huggingface.co/datasets/maxgfr/skycmd-zero-shot), [skycmd-series](https://huggingface.co/datasets/maxgfr/skycmd-series), [skycmd-text](https://huggingface.co/datasets/maxgfr/skycmd-text), [skycmd-ear](https://huggingface.co/datasets/maxgfr/skycmd-ear), [skycmd-lfm3-math](https://huggingface.co/datasets/maxgfr/skycmd-lfm3-math), [skycmd-cast-synth](https://huggingface.co/datasets/maxgfr/skycmd-cast-synth), [skycmd-evals](https://huggingface.co/datasets/maxgfr/skycmd-evals), [skycmd-trajectories](https://huggingface.co/datasets/maxgfr/skycmd-trajectories), [skycmd-glm-labels](https://huggingface.co/datasets/maxgfr/skycmd-glm-labels) (published with `scripts/hf-publish-data.py`; the GLM labels are AI-generated and marked as such).

A decision model does not generate text. It receives a **state** and **typed questions** (`choice`, `score`, `noul` = probabilistic yes/no) and returns a calibrated probability for every allowed option in **one forward pass**. skycmd shows how small such a model can be:

For comparison, `oscar-1-17m`, the smallest public model in this format, has 17M parameters, and the others range from 144M to 27B.

**s6-nano: one 715 KB model for the games and for questions in free text.** 1,486,225 ternary parameters, pre-registered in [`docs/s6-gen-prereg.md`](docs/s6-gen-prereg.md), and it passes its gate:

- **Above the majority class.** 0.480 on `typed_decisions_bench` (gate: > 0.398, the majority class), where s3-pico scores 0.382 and s4-micro 0.352 on the same records. s5-lite, with about 11 times as many parameters, scores 0.696.
- **What the gate did not measure** ([`docs/s6-nano2-study.md`](docs/s6-nano2-study.md), after the gate). A constant answer per task passes it: answering each question with its most common training answer scores 0.4815, and s6-nano 0.4805. On 17 of the bench's 20 tasks it gives one answer to at least 95% of the items; the bench's tasks were 0.4% of what it drew in decision training; a linear model of at most 715,136 bytes reaches 0.703 on the validation split of the same tasks. A narrower second version, the tool router s6-route-nano, was then pre-registered and trained once: it failed its gate (below).
- **Calibrated.** ECE 0.0479 over all the test sources, under the 0.08 guard.
- **Still plays.** Every game at s3-pico's score at full depth, at the oracle's level.
- **Published at full depth.** Its conformal exit thresholds lost 6.7% on Rescue Run and raised the Dodge vetoes from 23 to 1,016, so the pre-registered rule rejected them.
- **Its own failures.** NOTAM subject 0.055 and When2Call 0.404. Its sibling s6-micro (5.6M) scores 0.547 on the bench but misses the ECE guard (0.0821): it failed its gate; its file is published as a result (owner's decision of 15/11/2026), as s6-micro-v1. A second version, trained twice as long on decisions and designed after that reading, passed the same gate on the same test records (0.553, ECE 0.0588): it is published as s6-micro, and its pass is a second look. Every number, failures included, is on the [results page](https://maxgfr.github.io/skycmd/results/).

**s6-secrets-pico: a 250 KB secret detector that passes its gate on a synthetic bench and fails on real files.** 445,345 ternary parameters, pre-registered in [`docs/s6-secrets-prereg.md`](docs/s6-secrets-prereg.md):

- **Above the rule scanner on its synthetic bench.** On 1,996 texts in file types the training never shows (docker-compose, toml, go, ini), secret 0.9990 and service 0.9795, where a gitleaks-style rule scanner scores 0.977 and 0.787 on the same texts.
- **Four questions per text:** is a usable secret exposed, which service issued it, what kind of value it is (kind 0.9990), and on which line.
- **The line answer is weak.** 0.6859, and confident when wrong (ECE 0.3051). On the 1,010 texts that expose a secret it names the right line 383 times; the texts without one, where `none` is right, carry the score. Do not use it to locate a leak.
- **What the bench does not say.** The bench is synthetic: our generator's formats, file templates and class shares, with fake keys whose bodies are random. Beating the scanner there shows that the model reads formats and context in file types it never saw; it does not carry over to real files.
- **On real text it fails.** Measured after publication on 719 real source, configuration and documentation files in which a rule scanner finds nothing, cut into 22,433 chunks of at most 7 lines and 300 characters: at p ≥ 0.9 it flags 10.6% of the chunks and 59.8% of the files; at p ≥ 0.999, 5.9% and 49.4%. The flagged chunks are ordinary text (imports, prose, JSON), and the probabilities are not calibrated outside the generator (median 0.00009, 90th percentile 0.93 over the clean chunks). Recall on real secrets was not measured. The model stays published as the result of its pre-registration, not as a tool: do not use it to scan real files ([measurement](https://github.com/maxgfr/secretgate/pull/19), [`BENCH.md`](BENCH.md), amendment 6).
- **Published at full depth**, as its gate was read; try it on its bench texts on [Live](https://maxgfr.github.io/skycmd/live/#s6-secrets-pico-is-a-secret-exposed-in-this-text). Every number is on the [results page](https://maxgfr.github.io/skycmd/results/#s6-secrets-pico-passed-published-at-full-depth).

**s6-route: a 3.7 MB tool router that passed its gate on fresh slates, with a system defined after v2's test was read.** Pre-registered in [`docs/s6-nano3-prereg.md`](docs/s6-nano3-prereg.md); no training: the file of s6-route-nano (below, which failed its own gate), unchanged, fused option by option with potion-base-2M packed to 4 bits (MIT, Minish Lab), `p ∝ (p_model · p_embedding)^0.81`, and "ask the user" when the top probability is below 0.671047.

- **Disclosure.** v3 was designed after v2's test was read, from an exploratory reading of v2's test dumps. Its parameters come from validation. Its gate is read on requests no system had scored; on T2-tools these requests are about the same held-out tools as v2's test. The latency bar is 30 times v2's and was set after v2 was measured. The system needs distinctive tool names.
- **The gate held, every condition.** On 945 fresh requests about tools never seen in training, 0.8868, against BM25 0.8169 (+0.0698 [0.0455, 0.0952]) and all-MiniLM-L6-v2, 91.6 MB, 0.9048 (the bar was MiniLM − 0.03); above each of its two parts (0.7926 and 0.7386); never more than 0.02 below its better part on MetaTool, CLINC150 and MASSIVE; ECE 0.0162; 30.9 ms per request in WASM with the tool list cached (bar 60 ms), 3,692,224 bytes for the two files.
- **What the pass does not say.** Without the three largest clusters (645 slates) its advantage over BM25 is +0.0202 [−0.0062, +0.0481], and a bootstrap over clusters gives +0.0698 [−0.0079, +0.1404]: both intervals hold zero. With every tool renamed `tool_<k>` it falls to 0.2497, where BM25 keeps 0.8138. MiniLM is above it on every file. The announced goal of 0.95 among answered requests at coverage 0.80 is not met (0.9433 at 0.8593).
- **Try it** in the browser on the [Router](https://maxgfr.github.io/skycmd/router/) page: your own tool list and request, the probabilities of every tool and of *none*, and a button that masks the names. Every number is in [`BENCH.md`](BENCH.md) and on the [results page](https://maxgfr.github.io/skycmd/results/#s6-route-passed).

**s6-ear2-nano: a 632 KB end-of-turn detector that passed its gate.** Pre-registered in [`docs/s6-ear2-prereg.md`](docs/s6-ear2-prereg.md), trained once on an Apple M5 (240 working minutes, 305,700 steps), one task: given the last 4 s of 16 kHz audio it says whether the speaker has finished their turn, answering once when the VAD reports a pause. 1,306,178 ternary parameters, 631,936 bytes, a dedicated graph with Smart Turn's attention pooling and pitch, voicing and energy in its input.

- **The gate held, every condition.** On the 31,527 test clips of Smart Turn v3.2: accuracy 0.8993 [0.8962, 0.9027] (bar ≥ 0.85 and ≥ T − 0.08, with T = 0.9260 for Smart Turn v3.2 CPU through the same harness), above the silence timer (0.4979), v1 (0.5681) and v1's control (0.7647); at the validation threshold τ₈₅ = 0.7244, false cut-off 0.0847 (bar ≤ 0.20) and END recall 0.8627 (bar ≥ 0.80); 2.39 ms per decision in WASM (bar 5 ms), the front end 0.0186 ms per 10 ms hop, 631,936 bytes (bar 3 MB), WASM parity to 1.2e-7 with the same decision on 20 of 20 clips. AUC 0.9600, ECE 0.0160.
- **The sentence of §9.** Take v2 when size and speed matter: it gives up 2.7 points of accuracy against Smart Turn for a file of 0.63 MB instead of 8.7 MB and about 2.4 ms per decision in WASM instead of about 32 ms natively; take Smart Turn's file when those points matter more.
- **What the pass does not say.** On eot-bench, real conversational speech the design never read, v2 and its teacher are far weaker than on the test clips (AUC 0.7299 against 0.7838), and at τ₈₅ v2 answers "finished" on 0.5253 of the real ends of turn: about half pass. It is weakest on Vietnamese (0.7749), Marathi (0.7907) and Bengali (0.7950), and on the dataset mundo_1 (0.7843). The official test set is partly in-sample for v2's design choices, though never for its weights, and it is mostly synthetic speech.
- **No browser demo yet.** The engine API exists (`TurnDetector` in WASM, `sky-turn` natively); the demo needs the owner's microphone check first. Every number is in [`BENCH.md`](BENCH.md) and on the [results page](https://maxgfr.github.io/skycmd/results/).

**Five s6 models failed their gates; their files are published as results (owner's decision of 15/11/2026).** The verdicts do not change: each is recommended for no use, and its card, its manifest entry and its demo say first that it failed. s6-micro-v1 on calibration (ECE 0.0821 against 0.08; its second version, s6-micro, passed the same gate on the same test records, a second look), s6-ear-nano on three of its four gates (end of turn 0.5681 against 0.9263 for Smart Turn v3.2), and the forecaster s6-cast-pico on both of its metrics: on GIFT-Eval, nGMASE 0.9471 and nWQL 0.6646 against bars of 0.838 and 0.587, far from TinyCast's 0.774 / 0.545. The five models were trained in one run, from 12 to 14 November 2026; its final report, with every phase, incident and gate, is [`docs/big-run-report.md`](docs/big-run-report.md). The fourth is s6-secrets-verify-pico, the second version of s6-secrets ([`docs/s6-secrets2-prereg.md`](docs/s6-secrets2-prereg.md)): a verifier of the candidates of secretgate's rules, trained and tested on real repositories. On 221 CredData test repositories its line F1 is 0.8561, against 0.7332 for the best rule scanner: +0.123 where its gate asked for +0.15. Its six other gates hold (among them 0.35% of 8,825 clean real files flagged, ECE 0.0073, 1,606 µs per candidate natively), but it failed its gate on G1; its file is published as a result (owner's decision of 15/11/2026), and secretgate offers it since 1.9.0 only as an experiment, off by default (the rules' result is computed first and never changes) ([`BENCH.md`](BENCH.md)). The fifth is s6-route-nano, the second version of s6-nano as a decision model ([`docs/s6-nano2-prereg.md`](docs/s6-nano2-prereg.md)): a tool router that reads each tool's name and description, with each tool's BM25 score against the request in its state. On 2,000 test slates of tools never seen in training it picks the right option on 0.8395, above potion-base-2M with cosine (0.6675) and both trained baselines of its size, but not above BM25 (0.8500), which its gate asked it to beat; with every tool renamed `tool_<k>` it falls to chance (0.1050), and it takes 38.9 ms per request in WASM where the gate asked for 2 ms. It failed its gate on G1 and G4; its file is published as a result (owner's decision of 15/11/2026), with a Space that runs the file alone (owner's decision of 17/11/2026: every published model gets a Space) ([`BENCH.md`](BENCH.md)); its follow-up, the same file fused with a static embedding, passed its own gate as s6-route (above). **The s6-sleep experiment stopped at its pilot** ([`docs/s6-sleep-prereg.md`](docs/s6-sleep-prereg.md) §5): s6-pico with a fast-weight memory scored 0.2460 on the `recall` probe, against 0.2650 for the control without memory, where the rule asked for +0.10, so no nano run took place.

**LFM3-1.7B, System 1 first and System 2 when needed: failed** ([`docs/lfm3-s1s2-prereg.md`](docs/lfm3-s1s2-prereg.md), run on 14 and 15 November 2026, no weight trained). A 6-coefficient probe on the answer given without thinking decides whether to ask again with thinking on, with a threshold from conformal risk control (α = 0.02). On the 1,000 test questions (GSM8K and MATH-500), with the 1,024-token budget chosen on calibration: System 1 alone 0.667 at 559 tokens, System 2 alone 0.796 at 958, the router 0.786 at 1,032, the oracle 0.814. Accuracy kept (H2, yes), compute halved (H3, no), better than both modes (H4, no): the verdict is failure ([`BENCH.md`](BENCH.md), [results page](https://maxgfr.github.io/skycmd/results/#lfm3-s1s2)).

**s5-lite: a decision model whose options cannot see each other.** It is Ettin-17M, fine-tuned in Rust (mlx-rs), and ships as a 20.7 MB q8_0 GGUF in the `skycmd-iso` format.

- **Options read by definition.** Each option is read through its definition only, in isolation and at shared positions. Reordering the options or renaming their keys (the yes/no swap of 2609.26758) cannot change an answer; exact tests check this natively and in WASM.
- **Pre-registered bets, all missed.** The bets were fixed in [`docs/s5-prereg.md`](docs/s5-prereg.md), and the [results page](https://maxgfr.github.io/skycmd/results/) publishes every failure:
  - On the fitted bench, iso is far more accurate than the same encoder in the Laya format (0.674 against 0.429, 3 seeds), but its ECE is worse by 0.031 for a margin of 0.01.
  - The coherence losses only fix the identities they train.
  - 8-bit quantization moves the ECE by under 0.003 per seed, yet misses its pre-registered interval.
- **The model on [Live](https://maxgfr.github.io/skycmd/live/).** It is a longer run declared outside the bets. It scores 0.696 on `typed_decisions_test`, where oscar-1-17m scores 0.682 on the same records, and answers 21 of the 30 English demo cases. The page also has three proof demos: keys and order, paraphrases, and a Dutch book on the model's own probabilities.
- **No GLM outputs.** The teacher is laya-typed-decisions, run locally.
- **Story:** [chapter 23](https://maxgfr.github.io/skycmd/tutorial/23-s5-lite).

**s4-micro (experimental, before s5): a generic decision model.** 5.6M ternary parameters in a 2.4 MB `skycmd-s2` GGUF, with options in free text, distilled from Qwen3.5-4B in one night (`scripts/night-s4.sh`, [chapter 22](https://maxgfr.github.io/skycmd/tutorial/22-s4-generic-decisions)). It is still selectable on the [Live](https://maxgfr.github.io/skycmd/live/) page. It failed its gate: 0.343 on `typed_decisions_bench` (s3-pico 0.382, oscar-1-17m 0.6775, the teacher 0.501). It does better zero-shot on labels it never saw (Banking77 0.303 and MASSIVE English 0.335, 8 options each, against 0.247 and 0.187 for s3-pico), with ECE 0.066, but a fine-tuned 4.4M BERT-Tiny reaches 0.794 on Banking77. Language pretraining is the missing piece.

Two results took more than one try, and the tutorial tells both stories:
- **DAgger.** The first s1-pico labelled 82% of Flappy test states correctly and crashed in all 30 episodes before the first pipe. Relative clearances in the state text plus two DAgger rounds took it to 200/200. The 5.6× larger s1-nano did worse ([chapter 20](https://maxgfr.github.io/skycmd/tutorial/20-dagger-lessons)).
- **Early exit.** s2-nano crashed in every Flappy episode at the exit thresholds calibrated on validation questions (τ 0.62–0.69), and played at the oracle's level at full depth or with τ = 0.95, using 3.2 to 3.4 of its 4 layers. Calibrate the exit on closed-loop states ([chapter 19](https://maxgfr.github.io/skycmd/tutorial/19-s2-architecture)).

## How it works
- **s1 format.** The format is the same as Laya/Julia-1 and llama.cpp `/v1/systemone` ([PR #29818](https://github.com/ggml-org/llama.cpp/pull/29818)):
  - a ModernBERT encoder;
  - a decision head, run once per question type;
  - one `[MASK]` marker per option;
  - `softmax(score / T)` with temperatures per type and per option-count bucket.

  The same s1 `.gguf` file runs in our engine, in `llama-server` (max probability difference 4.7e-4) and in wllama 3.8.1 (1.1e-4), measured on the s1-pico checkpoint published before the DAgger rounds. Ollama 0.40.3 loads it but rejects the `laya` decision encoding ([`docs/compat.md`](docs/compat.md)).
- **s2 format** ([`docs/SPEC-S2.md`](docs/SPEC-S2.md)). Same requests and responses, different model: a static stream (question + options) encoded once and cached, a state stream encoded once per frame, options that never attend to each other (permutation-equivariant by construction), one `[NUM]` token per number with continuous value features, early exits with deep supervision, and ternary weights trained with QAT. s2 files run only in the skycmd engine: browser, Node/Deno/Bun, Python, CLI and server.
- **s3 format** ([`docs/SPEC-S3.md`](docs/SPEC-S3.md)). s2 with one token per `key value` pair (the value is added to the key's embedding), one weight-shared state block applied 4 times with an exit after each pass, and an exit threshold calibrated by playing the games (`scripts/calibrate-exit.sh`). s3 files keep the `skycmd-s2` architecture tag, so they run in the same places as s2 and nowhere else.
- **s4** ([`BENCH.md`](BENCH.md), s4 section; [chapter 22](https://maxgfr.github.io/skycmd/tutorial/22-s4-generic-decisions)). s3 at language scale, for questions written in free text:
  - 2 state blocks × 3 loops with exits at 2, 4 and 6, and 4 heads;
  - d 256, vocabulary 4,096;
  - state and head budgets of 384 and 128 tokens;
  - distilled from Qwen3.5-4B in one night (`scripts/night-s4.sh`).

  s4 files keep the `skycmd-s2` tag.
- **iso format, s5** ([`docs/s5-prereg.md`](docs/s5-prereg.md), [results](https://maxgfr.github.io/skycmd/results/), [chapter 23](https://maxgfr.github.io/skycmd/tutorial/23-s5-lite)). The `skycmd-iso` GGUF on a pretrained encoder (Ettin-17M):
  - the state is encoded once and reused across questions;
  - each option is read through its definition only, in isolation and at shared positions.

  Reordering the options or renaming their keys cannot change an answer, by construction, and exact tests check it natively and in WASM. It is fine-tuned in Rust from the laya-typed-decisions teacher's soft labels, and ships in q8_0.
- **s6 format** ([`docs/SPEC-S6.md`](docs/SPEC-S6.md)). s3 with Parallax attention: a learned probe corrects softmax attention with the covariance of the values and the keys (arXiv 2605.29157). It is trained with the Muon v2 recipe: Kimi's decoupled decay and AdamW-matched update scale, and a two-stage Newton–Schulz. s6 files keep the `skycmd-s2` tag. Other additions, each optional:
  - exclusive self-attention (`xsa`);
  - SODA weight decay;
  - exit self-distillation;
  - exit thresholds by conformal risk control (`sky-arena --calibrate-crc`).

  `cargo xtask s6ab` runs the {AdamW, Muon v2} × {softmax, Parallax} ablation, then tests each addition on its own. Its pre-registered rules adopted none of them (`runs/recipe/recipe.json`): s6-nano and s6-micro train with AdamW, softmax attention and none of the options. What changed from s3 and s4 is the pretraining, the GLM teacher, the tokenizer and the windows. s6 pretrains on more text than s3: the stories and web of `data/text`, plus `data/text-open`, the non-web parts of the published training data of two fully open LLMs (Dolma 3 for OLMo 3, TxT360 for LLM360): Wikipedia, science PDFs, maths, public-domain books, StackExchange and French Europarl.
- **s6-nano and s6-micro** ([`docs/SPEC-S6.md`](docs/SPEC-S6.md) §15, [`docs/s6-gen-prereg.md`](docs/s6-gen-prereg.md), trained; s6-nano published; the first s6-micro failed its gate, its file is published as a result (owner's decision of 15/11/2026) as s6-micro-v1; the second version passed the same gate on a second look and is published as s6-micro). The s6 that ships is general-purpose: the four games and questions in free text, in two sizes. The pico ablation chose the recipe and there is no s6-pico final model.
  - **s6-nano** has 1,486,225 parameters, 2,048 tokens and 512/160-token windows. Without Parallax, which the ablation did not adopt, it has fewer parameters than the 1.57M of the pre-registration.
  - **s6-micro** has 5,587,201 parameters: the s4-micro shape, 4,096 tokens and 384/128-token windows.

  Both pretrain for hours on 300 MB of text (s4-micro had 30 minutes on 150 MB) and train on the decision sets, the games and the numeric curriculum, plus soft labels on every training question of the Hugging Face decision sets (about 747,000). The teacher is GLM-5.3-flash, an open-weight model (MIT), called through the z.ai API: `caffeinate -i scripts/distill-glm.sh loop mix` labels everything remotely, resuming across the 5-hour usage windows of a z.ai plan, so the machine stays cool.
  - **s6-nano gate:** beat the majority class of `typed_decisions_bench` (0.398). **Passed:** 0.480, ECE 0.0479, every game at s3-pico's score. A constant answer per task passes this bar too (the most common training answer of each question scores 0.4815; `docs/s6-nano2-study.md`).
  - **s6-micro gate:** at least 0.45, with 0.50 as the goal (the level of s4's Qwen3.5-4B teacher). **Failed on calibration only:** 0.547 (gate and goal met), but ECE 0.0821 at full depth and 0.0804 at its conformal thresholds, above the 0.08 guard. Its decision training was stopped once for a memory problem and resumed from its checkpoint (amendment 11). **The second version passed** (amendments 12, 16 and 17): 360 minutes of decision training instead of 180, everything else the same, 0.553 on the bench and ECE 0.0588 (bootstrap interval [0.0526, 0.0687]), the games at s3-pico's scores, published at full depth as s6-micro. It was designed after v1's ECE failure and judged on the same test records, so its pass is a second look; its training was resumed once from its checkpoint after a file-access error, and the end of the run shared the machine with other jobs.

  Each gate also requires no game more than 5% below s3-pico and an ECE of at most 0.08.
- **s6-cast** ([`docs/SPEC-S6-CAST.md`](docs/SPEC-S6-CAST.md), [`docs/s6-cast-prereg.md`](docs/s6-cast-prereg.md); the first s6-cast-pico failed its gate; its file is published as a result (owner's decision of 15/11/2026): on GIFT-Eval, nGMASE 0.9471 and nWQL 0.6646 against bars of 0.838 and 0.587, and TinyCast's 0.774 / 0.545; see [`BENCH.md`](BENCH.md)). A probabilistic forecaster built on the s6 encoder: up to 2,048 past points in patches of 32, nine quantiles for each of the next 64 steps, ternary (142,912 bytes for the trained pico, 369,792 parameters), designed for under 1 ms per forecast on one CPU core (its latency was not measured in this run). It is pretrained on synthetic series from Rust generators (Gaussian-process kernels, pulses, trend + seasonality, SARIMA). `sky-train cast-train` trains it, and `sky-cast` forecasts from the command line.
- **s6-ear** ([`docs/SPEC-S6.md`](docs/SPEC-S6.md) §16, [`docs/s6-ear-prereg.md`](docs/s6-ear-prereg.md); the first s6-ear-nano failed its gates; its file is published as a result (owner's decision of 15/11/2026): end of turn 0.568 against 0.926 for Smart Turn v3.2 (Pipecat's report; the v1 harness read 0.8518), keywords 0.889 for a bar of 0.90, zero-shot French keywords 0.133 for a bar of 0.20). An s6 that listens. Its state is 10 s of 16 kHz audio, as one 320-value log-mel frame every 80 ms (Mimi's frame rate), computed in Rust natively and in WASM. The questions and options stay text, so it can be asked about words it never heard in training. It pretrains by predicting, for masked frames, the semantic codebook of Kyutai's Mimi codec from published codes, without ever running Mimi. It answers the decisions of a voice agent: has the speaker finished, which word was said, and later "keep listening, acknowledge, speak or yield". Conformal thresholds tell it when to hand the clip to a larger model. In the browser: `Engine.decideAudio`. The bar is Smart Turn v3.2 (8M parameters) at 1/5 of its size.
- **s6-secrets** ([`docs/SPEC-S6.md`](docs/SPEC-S6.md) §14, [`docs/s6-secrets-prereg.md`](docs/s6-secrets-prereg.md); s6-secrets-pico passed its gate and is published: secret 0.9990 and service 0.9795 on the synthetic bench, against 0.977 and 0.787 for the rule scanner, line 0.6859. Measured afterwards on real files with no secret, it flags 59.8% of them at p ≥ 0.9: it is not a scanner. Its second version, s6-secrets-verify-pico, a different task with its own pre-registration in [`docs/s6-secrets2-prereg.md`](docs/s6-secrets2-prereg.md), failed its gate on G1: line F1 0.8561 against 0.7332 + 0.15 for the best rule scanner on 221 CredData test repositories; its file is published as a result (owner's decision of 15/11/2026), and secretgate offers it since 1.9.0 only as an experiment, off by default (the rules' result is computed first and never changes). Its third version, s6-secrets v3 ([`docs/s6-secrets3-prereg.md`](docs/s6-secrets3-prereg.md)), is not a new model but secretgate's default rules and this verifier together, judged on the same seven gates on a second look at the same test files, with the system defined after the first reading: G1 failed again on every repository, 0.8477 against 0.7332 + 0.15 (the model alone was at 0.8561), the six other gates hold, and the work on this model ends). A decision model specialized in API-key and secret detection. It keeps the s6-pico architecture, with a 320-token state window, and reads a short text (`.env`, code, config, `curl`, log, diff). It says whether a usable secret is exposed, which service issued it, what kind of value it is (secret, test key, publishable key, placeholder, or no credential) and on which line. Its data is a synthetic jev (`sky-data secret-jev`) whose keys follow each provider's format with random bodies. The bench uses file types the training never shows. The bar to beat is a gitleaks-style rule scanner: 0.977 on the secret question and 0.787 on the service.
- **Training.** Everything is in Rust with [mlx-rs](https://github.com/oxiglade/mlx-rs) on Apple Silicon:
  - MLM pretraining;
  - decision training with cross-entropy on soft targets;
  - Muon for the encoder matrices (recipe 2: decoupled decay, `0.2·√max(A, B)` scale, Newton–Schulz with polish iterations) and AdamW for the rest, with a WSD schedule;
  - per-type temperature calibration;
  - DAgger rounds on the games;
  - for s2: numeric MLM, deep supervision over the exits and ternary QAT;
  - for s3: a numeric curriculum, loop dropout and closed-loop exit calibration;
  - for s4: distillation of a teacher's soft labels with deep improvement supervision (`--dis`);
  - for s5: iso fine-tuning of a pretrained encoder (`sky-train s5-train`), with optional coherence losses;
  - for s6: Muon v2, exit self-distillation, weight EMA and exit thresholds by conformal risk control (the pre-registered ablation adopted none of them for s6-nano and s6-micro).
- **Data.** Most of it comes from Hugging Face:
  - typed-decision sets plus BoolQ, MNLI, ARC, CommonsenseQA and Banking77;
  - SimpleStories, TinyStories and FineWeb for pretraining;
  - game states labelled by exact oracles;
  - paraphrases generated by GLM.

  See [`DATA_LICENSES.md`](DATA_LICENSES.md).
- **Inference.** A dependency-light Rust engine (byte-level BPE, ModernBERT and s2 graphs, f32, Q8_0 and ternary weights) compiled to `wasm32` with SIMD128, and packaged as the `skycmd` CLI and server, a Python wheel and an npm package ([Install](https://maxgfr.github.io/skycmd/install/)). In the browser, one WASM call runs the game physics, turns the state into text, runs the model, applies the coded safety veto and steps the game.

## The rule: the model proposes, the code decides
The games are civil drone scenarios: Flappy Drone, Rescue Run and Obstacle Dodge. In each one the model only *advises*, and coded rules (geofence, ceiling, battery, collision reflex) always keep a veto. This is a demo and a tutorial, not flight software. The model never touches a control loop.

A fourth game is a Doom-like first-person shooter on a grid, drawn with [Freedoom](https://github.com/freedoom/freedoom) art (BSD-3-Clause; no id Software assets). The same kind of model plays it from 14 measured numbers every 4 ticks, with a coded reflex against fireballs and empty weapons ([chapter 18](https://maxgfr.github.io/skycmd/tutorial/18-doom), `scripts/train-doom.sh`).

## Quick start (macOS, Apple Silicon)
```sh
xcodebuild -downloadComponent MetalToolchain            # MLX needs the Metal compiler
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
scripts/prepare-data.sh                                   # every dataset below, from scratch (FORCE=1, REFRESH=1)
cargo run --release -p sky-data -- fetch-decisions        # Hugging Face → data/decisions
cargo run --release -p sky-data -- fetch-text
cargo run --release -p sky-data -- fetch-text --set open    # Dolma 3 + TxT360 → data/text-open (s6 pretraining)
cargo run --release -p sky-games --bin sky-games-gen -- --game all --n 60000 --seed 1
cargo run --release -p sky-data -- train-tokenizer --vocab 1024
scripts/train-ladder.sh pico                               # pretrain → decide → calibrate → export → eval
scripts/specialize.sh pico 2 6                             # DAgger rounds on the games
cargo run --release -p sky-arena -- models/s1-pico-g2 --episodes 30
cargo run --release -p sky-data -- train-tokenizer --vocab 2048 --num   # s2 tokenizer with [NUM]
CARGO_TARGET_DIR=$PWD/target/sky-infer-s2 cargo build --release -p sky-arena
scripts/train-s2.sh nano && scripts/specialize-s2.sh nano 2 8      # the s2 model (chapter 19)
cargo run --release -p sky-data -- train-tokenizer --vocab 1024 --num   # s3-pico tokenizer
cargo run --release -p sky-games --bin sky-games-gen -- --game doom --n 100000 --seed 1 --out data/games/doom.jsonl
CARGO_TARGET_DIR=$PWD/target/s3-arena cargo build --release -p sky-arena
scripts/train-s3.sh numeric pico && scripts/specialize-s3.sh pico 3 8   # the s3 model (chapter 21)
scripts/calibrate-exit.sh models/s3-pico-g3/skycmd-s3-pico-g3-ternary.gguf s3-pico.gguf   # closed-loop τ
scripts/night-s4.sh                                        # s4-micro: Qwen3.5-4B teacher, distillation, gate (chapter 22)
export SKYCMD_STORE=$PWD && cargo xtask s5 list             # s5-lite: every stage of the pre-registered run (chapter 24)
cargo xtask s6lr && cargo xtask s6ab --adamw-lr-scale 1 --muon-lr-scale 1   # s6: learning-rate pilot, then the ablation
SIZE=nano scripts/train-s6.sh lr train dagger exit eval    # s6-nano, then SIZE=micro (docs/s6-gen-prereg.md)
scripts/train-cast.sh data pilot                           # s6-cast: data, then the pre-registered pilots
scripts/train-cast.sh train export eval                    # s6-cast: training, export, GIFT-Eval (docs/s6-cast-prereg.md)
scripts/train-secrets.sh data train eval                   # s6-secrets-pico: jev, training, bench vs the rule scanner
scripts/train-ear.sh data pretrain decide eval             # s6-ear-nano: audio data, Mimi pretraining, gates vs Smart Turn
```
To use a published model without training anything, see the [Install](https://maxgfr.github.io/skycmd/install/) page.
The step-by-step guide is the [tutorial](https://maxgfr.github.io/skycmd/tutorial/).
