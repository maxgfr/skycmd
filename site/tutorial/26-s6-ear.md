# 26 s6-ear: a decision model that listens

*Code ready and tested end to end on a small sample (3 November 2026). No model is trained yet, so this chapter has no results: the gates below will say whether it ships.*

Every model so far reads its state as text. s6-ear reads **audio**: the last 10 seconds of speech, at 16 kHz. It answers typed questions about them with the same engine, the same GGUF format, the same early exits and the same WASM build as the game models. These are the decisions a voice agent needs every 80 ms: has the speaker finished, which word was said, and later whether to keep listening, acknowledge, speak or yield.

## The idea: keep the semantic tokens, drop the codec

The starting point is a talk by Neil Zeghidour (Kyutai). A neural codec such as SoundStream or Mimi turns audio into "almost characters", a few codes per frame, and a language model can then predict those codes like text. That is how AudioLM, Moshi and their full-duplex agents work. One remark in it fits skycmd well: a *small* model holds the conversation and calls a large one when it does not know.

The codecs themselves are not small:

| | parameters |
|---|---:|
| Mimi encoder (Kyutai) | about 48M |
| SNAC | 19.8M |
| EnCodec | 15M |
| **s6-ear-nano, the whole decision model** | **1.6M** |

Two published results settle the design:

- **Continuous features beat discrete indices** for classification (DASB, arXiv 2406.14294; DualTurn, arXiv 2603.08216).
- **Mimi's first codebook is semantic.** Kyutai distilled it from WavLM, and its codes for LibriSpeech are already published under CC-BY-4.0 (`shangeth/librispeech-mimi-codes`).

So s6-ear never runs a codec. It reads cheap log-mel features and **learns to predict Mimi's semantic codes** during pretraining. The teacher's knowledge goes into 1.6M ternary-friendly weights, and Mimi never runs on our machine.

## A front-end you can read in one sitting

`crates/sky-infer/src/audio.rs` has no dependency:

- **Spectrum:** a 25 ms periodic Hann window, a 10 ms hop and a 512-point radix-2 FFT.
- **Bands:** 40 mel bands from 20 Hz to 8 kHz, then `y = (log10(max(mel, 1e-8)) + 2) / 4`.
- **Frames:** 8 hops are stacked into **one state frame of 320 values every 80 ms**, exactly Mimi's 12.5 Hz frame rate. The state is the last 128 frames (10.24 s).

The same file runs natively, in the browser and in the data pipeline that writes the training features. Training therefore sees exactly the frames the engine computes at inference.

**The smart detail: a log without libm.** The first WASM parity test failed by 3e-5. The cause was `f32::sin` in the test signal and, potentially, `log10` in the front-end: libm differs by one ULP between macOS and WASM. The front-end now computes its log from IEEE basic operations only (an `atanh` series), and the test signal is generated by a rotation recurrence. Native and WASM features now agree to 1e-12, and the decisions to 2.4e-7.

## The model: s6-nano with an ear

`configs/s6-ear-nano.json` keeps the s6-nano shape: d = 144, 2 blocks looped twice, four early exits, Parallax attention. The only change is the state stream:

- **The frame projection.** `audio_proj · frame + bias` (`[144, 320]`, float, like s6-cast's patch projection) replaces the token table, with one state position per 80 ms frame.
- **The question stays text.** The question and its options are still BPE text in the static stream, so you can ask about words the model never heard in training. A classic keyword spotter has a fixed output layer and cannot do that.
- **The format.** Two GGUF keys, `state_kind = "audio"` and `audio_frame = 320`. A file without them is an ordinary text model, byte for byte.

**Parameters** (fixed by a test): 1,615,681 for the decision model, which is s6-nano plus the 46,224 of `audio_proj`. That is 1/5 of Smart Turn v3.2, the 8M end-of-turn detector we compare against.

## Pretraining: "Mimi as the teacher"

`sky-train s2-pretrain --audio` runs BEST-RQ / HuBERT-style masked prediction:

1. Crops of up to 128 frames, 30% of them masked in spans of 3.
2. Each masked frame's projection is replaced by a learned mask vector.
3. A small head predicts the frame's Mimi codebook-0 id, out of 2,048 classes.

The pretraining stack has no token table at all, and the 2,048-class head is dropped when the decision model starts. In the smoke run, the loss left the uniform value (7.6) within 30 steps, at about 100,000 frames per second on an M5.

## The audio jev

`sky-data fetch-audio` and `sky-data audio-jev` turn public CC-BY-4.0 clips into decision records, one per question:

| question | type | data |
|---|---|---|
| "Has the speaker finished their turn?" | noul | Smart Turn's data (23 languages, French included) |
| "Which word was said?", 12 options | choice | Speech Commands v0.02, the standard benchmark |
| the same question on **words never trained on** | choice, 10 options | MSWC, English and French: 50 words per language held out |
| later: "What should I do now?" (listen, backchannel, speak, yield) | choice | AMI, by a pre-registered rule |
| later: questions about the content | noul / choice | GLM-5.3-flash reads the LibriSpeech *transcripts*, and s6-ear learns to answer from the *audio* |

The last row is **cross-modal distillation**. The teacher that already labels text for s6-nano also labels what was said, and the student learns to answer from the sound. That replaces the spoken-intent datasets, which are all non-commercial (Speech-MASSIVE, SLURP).

## Two choices made for honesty, before any run

- **The right test set.** The plan drew the end-of-turn test clips from `smart-turn-data-v3-train`. That is Smart Turn's own training set, so the bar would have been measured on data the baseline had memorized. The test is now Pipecat's official held-out set, `smart-turn-data-v3.2-test`, and every train clip with a test id is removed.
- **A fair zero-shot test.** Each held-out word gives exactly 20 test questions, so the right answer is uniform over the held-out words, and no frequency prior can pass for hearing.

Both choices are written into the [pre-registration](https://github.com/maxgfr/skycmd/blob/main/docs/s6-ear-prereg.md) before any full download or training.

## System 1, with a guarantee

Two thresholds per question type, both chosen by conformal risk control on the val split (`scripts/ear-gate.py crc`):

- **Early exit**, as for the games: answer at the first exit that is confident enough. The answer may differ from full depth in at most α = 2% of the cases.
- **Hand-off to System 2:** below a second threshold, s6-ear says "I don't know" and passes the clip to a larger model (Whisper, Smart Turn). The error among the decisions it keeps is bounded by 5%.

This is the routing tested on LFM3-1.7B, applied to voice. A tiny frontal model decides every 80 ms, and the large model is called only when an answer is really needed. Kyutai's MoshiRAG does the same with a 7B frontal model.

## The gates

Fixed in advance, read on the ternary model at full depth:

1. **End of turn** at least as accurate as Smart Turn v3.2 on the same clips.
2. **Speech Commands** (12 classes): at least 0.90.
3. **Zero-shot keywords**: at least 2 × chance (0.20) in English **and** in French.

A control is trained alongside: the same model and budget **without** the Mimi pretraining, so the report shows what the distillation brings.

## Try it

```bash
MAX_CLIPS=200 scripts/train-ear.sh data      # smoke data: 200 clips per set
scripts/train-ear.sh data pretrain decide eval
```

The [Listen](/ear/) page runs it on your microphone or on sample clips once the model ships. In your own page:

```js
const r = JSON.parse(engine.decideAudio('noul', 'Has the speaker finished their turn?',
  JSON.stringify(['false: still talking', 'true: finished']), pcm16k))  // Float32Array
```

The measured costs in the smoke run, both at full depth:

- **Native:** 0.6 ms per decision for 1 s of audio and 5 ms for 10 s, log-mel included.
- **WASM:** 0.67 ms per decision (median over 20 clips).
